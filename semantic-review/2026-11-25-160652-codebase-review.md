# Full-stack document request system for CEIT DRAMS

This is a custom PHP MVC application that lets CEIT students submit document requests (thesis proposals, clearance forms, etc.) and lets admin/staff review and disposition them. The architecture is intentionally lightweight: a hand-rolled router, PDO for database access, session-based auth, and a flat helper file for shared logic. The system is at a mid-construction state — the UI is complete and the database layer is live, but several security controls are incomplete or only partially wired.

**Watch for:** The register form exposes `admin` as a selectable role, letting any visitor self-escalate to admin (confirmed). Session fixation is not addressed on login (confirmed). Logout is a GET route calling `csrf_verify()` on `$_POST`, so it always returns 403 (confirmed). None of the form views emit a `_csrf` hidden field, so every POST currently returns 403 (confirmed). `csrf_token()` and `csrf_verify()` are defined twice in `helpers.php`, with the second copies silently dead (confirmed).

**Verdict**: NEEDS_CHANGES

---

## High-level view

Authentication uses `password_hash`/`password_verify` correctly, but misses two foundational steps: `session_regenerate_id(true)` is never called on login, and logout is wired as a GET route that calls `csrf_verify()` — which reads `$_POST['_csrf']` and therefore always fails with 403, making logout completely broken.

The register form presents `admin` as a `<select>` option labeled "CEIT Student Council". The backend validates the submitted value against `['student', 'admin']`, which accepts it. Any visitor can self-register as an admin.

`csrf_verify()` is called on every POST handler, but none of the view templates emit the `_csrf` hidden field. Every POST in the application currently returns 403. This and the broken logout strongly suggest the CSRF scaffolding was added to controllers before the view wiring was completed.

`helpers.php` defines `csrf_token()` and `csrf_verify()` twice, both times under `if (!function_exists(...))` guards. Only the first copy runs. The second `csrf_verify()` uses a 419 status code and a different error message — an intentional change that was never applied because the duplicate guard blocks it.

Cross-request data isolation is correct: `find_request()` appends `AND r.user_id = :uid` for student queries, so a student cannot access another student's request or its attachment by guessing the ID. The attachment download endpoint uses `find_request()` for this check.

The document catalog (`app/data/documents.php`) is a static array merged with live request data at render time. `queue_requests()` already scopes results to the logged-in user, so the computed per-document access state is correctly user-scoped.

The `.env` file contains `DB_USER=root` with an empty password and there is no visible `.gitignore`. If this repository is pushed to a remote, credentials ship with it.

The admin queue fetches all rows from `document_requests` and filters/sorts them in PHP. For a university department's queue this is acceptable now, but it won't scale past a few thousand rows.

<details>
<summary>Issues (9)</summary>

1. **Self-registration as admin** — The register form exposes `admin` as a `<select>` option, and the backend accepts it. Remove the `admin` option from the registration form entirely; role elevation should require an existing admin.

2. **Session fixation on login** — `AuthController::login()` writes `$_SESSION['auth_user']` without calling `session_regenerate_id(true)` first. Any session ID established before login is promoted to an authenticated session. Add `session_regenerate_id(true)` immediately before the session write.

3. **Logout is broken** — `/logout` is a GET route. `csrf_verify()` reads `$_POST['_csrf']`, which is always empty on GET, so every logout returns 403. Convert logout to a POST route with an inline form and CSRF token, or drop `csrf_verify()` from logout and use a query-string nonce instead.

4. **CSRF hidden field missing from all forms** — `csrf_verify()` is called on login, register, and all admin actions, but none of the form views emit `<input type="hidden" name="_csrf" ...>`. Every POST returns 403 until this is added to `auth/login.php`, `auth/register.php`, `requests/create.php`, and `components/decision-actions.php`.

5. **Duplicate CSRF function definitions** — `helpers.php` defines `csrf_token()` and `csrf_verify()` twice under `if (!function_exists(...))` guards. The second copies (with 419 status) are silently dead. Remove the duplicate block.

6. **`APP_DEBUG` hardcoded to `true`** — `config.php` sets `APP_DEBUG` unconditionally. Gate it on an environment variable so production defaults to `false`.

7. **No `.gitignore`** — `.env` contains database credentials and there is no `.gitignore` in the repository. Add one excluding at minimum `.env`, `storage/uploads/*`, and `storage/logs/*`.

8. **No form input re-population on validation failure** — On login or register error, the controller redirects with a flash message but no preserved field values. All inputs clear on each failed submission. Stash the safe fields (email, name, student number — never password) in the session alongside the flash and re-populate them in the views.

9. **Duplicated role redirect guard across five controller methods** — `HomeController::index()`, `HomeController::profile()`, `RequestController::create()`, `RequestController::store()`, `RequestController::index()`, and `RequestController::documents()` all repeat `if (auth_user()['role'] === 'admin') { $this->redirect('/admin'); }`. Move this into `admin_guard()` or add a `student_guard()` helper, and call it once per method.

<details>
<summary>Details</summary>

### Open admin self-registration

`register.php` renders:

```html
<select id="account-type" name="role" required>
    <option value="student">Student</option>
    <option value="admin">CEIT Student Council</option>
</select>
```

`AuthController::register()` validates the value against `['student', 'admin']`, which accepts it and inserts the row with `role = 'admin'`. The label "CEIT Student Council" is cosmetic — the submitted value is `admin`. Remove the option from the view. Admin provisioning should happen out-of-band (seeded account, or an invite flow reachable only by an existing admin).

### Session fixation on login

`AuthController::login()` writes to `$_SESSION['auth_user']` after verifying credentials but never calls `session_regenerate_id(true)`. PHP starts a session automatically for the CSRF token when the login page loads, so the session ID is established before authentication. That pre-auth session ID is promoted to an authenticated session, which is the classic fixation vector.

```php
// Add this immediately before $_SESSION['auth_user'] = [...]:
session_regenerate_id(true);
```

### Broken logout

`/logout` is a GET route in `index.php`. `AuthController::logout()` calls `csrf_verify()`, which does:

```php
$token = (string) ($_POST['_csrf'] ?? '');
if (!hash_equals((string) ($_SESSION['csrf_token'] ?? ''), $token)) {
    http_response_code(403);
    exit('Invalid CSRF token.');
}
```

On a GET request `$_POST['_csrf']` is `''`, which never matches the stored token. The sidebar renders logout as `<a href="...">`, confirming it fires a GET.

Converting to POST also fixes the secondary concern: a GET `/logout` can be triggered by a third-party page via `<img src="...">`, silently logging the user out (logout CSRF).

### CSRF fields absent from all forms

Five view files need the hidden field before CSRF protection works:

- `app/views/auth/login.php` — login form
- `app/views/auth/register.php` — register form
- `app/views/requests/create.php` — request submission form
- `app/views/components/decision-actions.php` — all five admin decision forms (each is a separate `<form>`)

A `csrf_field()` helper that returns the rendered `<input>` would keep this DRY.

### Duplicate CSRF definitions

The second block in `helpers.php` (around line 185) redefines `csrf_token()` and `csrf_verify()` with a 419 status code. Because the first definitions are also inside `if (!function_exists(...))` guards, the second block's guards evaluate to false and the functions are never redefined. The 419 behavior is unreachable. This is a merge error — remove the second block.

### `APP_DEBUG` hardcoded

```php
define('APP_DEBUG', true);  // config.php
```

The constant is not currently read anywhere to gate error display, but it communicates developer intent and future code may rely on it. The fix:

```php
define('APP_DEBUG', (bool) (getenv('APP_DEBUG') ?: false));
```

### .doc MIME detection gap (possible)

`handleAttachment()` allows `application/octet-stream` as a valid detected MIME for all upload types. A `.doc` file containing arbitrary content passes validation as long as the extension is `.doc`. For this application's threat model (internal, authenticated users) this is low risk, but if the allowed types ever expand to executable extensions (`.js`, `.php`), the extension-only check would become a path to stored XSS or code execution.

### Request ID sequencing under load

The sequence query uses `FOR UPDATE` on a `LIKE` scan of the primary key varchar column. Under low concurrency this serializes correctly. If multiple requests arrive in the same second, `LIKE 'DR-20261125-%' FOR UPDATE` may scan the entire index range for that day. A surrogate `AUTO_INCREMENT` column alongside the human-readable ID string would be more robust and would remove the transaction complexity.

### Dead mock data file

`app/data/mock_dashboard.php` is no longer referenced anywhere — all controllers query the live database. Delete it to avoid confusion about which data is authoritative.

### Undefined `$context` variable in dashboard view

`app/views/home/index.php` uses `$context` in filter chip URLs:

```php
href="<?= url('/dashboard') ?>?context=<?= e($context) ?>&amp;filter=all"
```

`HomeController::index()` does not pass a `$context` key in the view data. PHP will produce a notice (or in strict mode, an error) and the variable evaluates to an empty string. Remove `$context` from the URLs or define and pass it from the controller.

</details>
